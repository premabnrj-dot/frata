Themes or code: which storefront should Frrata bet on?

You're right to be skeptical. An agent writing free code scores worse than today's themes on almost everything that protects a shop: speed, security, consistency, upkeep. It wins only on how far a site can go and on giving partners something to sell. The version worth building is code written on a Frrata design system, where the brand, components, motion, speed, SEO and safety come built in and a check refuses anything that drifts.

What carries over from today

Most of the theme work becomes the kit rather than being thrown away: the section renderers and product parts become kit components; theme settings and the site palette become the brand kit; the gates (colour, scale, motion, contrast, voice, fonts, credits, client bundle, payload, page budgets) become publish checks; the Signal and Classic looks become the first two starters. The customizer and the theme catalogue are what actually go.

What changes in the plan

Kit before builder. V1.5 inserted: the Frrata kit (package, brand kit in the console, publish checks) built from today's storefront code, before hosting (V2) and Studio (V3).
Brand kit first. A new site starts at the brand kit; the console's Look turns into the brand kit, not removed.
Starter 0. Today's renderer, exported as the default starter, so every shop has a complete site on its first day.
Your call. Go with C (code on Frrata's kit) and insert V1.5, or keep A (themes) for brands without partners and run C beside it?
