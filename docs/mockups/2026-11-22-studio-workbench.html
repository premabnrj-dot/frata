In short

Why does a key need a domain first?

It no longer does. Since 16 Nov a Test key works with no domain. The Website page still shows a disabled “Connect a domain first” box. It reads as required. Screen 2 removes the box. A Live key does need a proved address, as Razorpay’s live keys do.

Checkout on a second address

One address is approved (ADR-0019). It waits for the secure frame, and the reviews confirm it must. So the frame moves to the front of the queue. The reviews also found a gap. A store that has not opened takes no orders, so nobody can test checkout before opening day. Screen 3 adds test orders.

Is the Studio screen right for developers and designers?

The approved screen suits a partner talking to the agent. It has no code view, no checks list, no page states and nothing collapses. Screen 1 keeps the approved chat and preview and adds a third panel. All three collapse.

How do developers use apps on a website?

Today they mostly cannot. No app gives a website anything to read. Product video never reaches a website. The PIN code check works on theme stores only. A website cannot tell which apps are on. Screen 4 gives every app three parts. Data, a ready block and a Frrata-drawn screen for anything personal.

What keeps docs in step, for every app to come?

Docs are generated from the API’s own schemas already. Nothing fails when a route or an app is missed. Screen 5 lists eight rules. A gate that fails the build holds each one.

What it costs and what I need

Three small items can start now with no owner account. The rest re-orders work already approved. I need your answers to the ten calls. Three owner steps are open. They are Vercel teams, the preview domain and the frrata.shop renewal.

What to take

Each vendor’s own page, read 22 Nov 2026. “Undated” means the page is live but carries no date.

Lovable

Chat left, preview right. One shortcut hides chat and gives the preview the window. [ folds the sidebar. The preview toolbar has four modes: select, edit text, draw, comment. Desktop, tablet and mobile widths.

docs.lovable.dev/features/projects/editor, /preview-toolbar · 20–22 Nov 2026Take: fold with one key; select, edit and note on the preview; three widths.

Bolt

Chat and preview by default. A code icon opens the file list and editor. Visual edits are free and batch up. Credits are spent only on save.

support.bolt.new/building/code-view, /visual-edits · 11–16 Nov 2026Take: code behind one tab; hand edits cost nothing.Skip: a terminal in the browser.

v0

Design Mode opens a panel for type, colour and spacing on the picked element. A note carries a screenshot of that element. Apply makes a version. A branch for each chat, with its own preview.

v0.app/docs/design-mode, /github · 20 Nov 2026Take: the Design tab; a note pinned to a part; Apply makes a version.Skip: free colour and spacing. Ours come from the brand record’s scales.

VS Code and Figma

VS Code folds its side bar with one key and has a mode that hides everything. Figma can minimise the panels or hide them all. The right panel returns when something is picked.

code.visualstudio.com/docs/getstarted/userinterface · 18 Nov 2026 · help.figma.com · undatedTake: Preview only; the inspector returns when a part is picked.

Shopify (Hydrogen)

Products and cart read with no key. Browsers use a public key. mock.shop gives demo data. Checkout sits on a subdomain such as checkout.example.com. Hydrogen does not draw app blocks. A developer reads the app’s data, calls its API or adds its script.

shopify.dev/docs/storefronts/hydrogen/deploy/go-live, /installed-apps · undated, API 2026-10Take: build before any domain; sample data.Skip: the checkout subdomain, and apps left for each developer to wire.

Stripe and Razorpay

Test keys work at once. Razorpay makes them “without adding a website” and asks for one on live keys. Stripe’s embedded checkout mounts on your page with a return address. Monthly versions never break. The API description is public and builds the SDKs.

docs.stripe.com/keys, /api/versioning · version 2026-11-18 · razorpay.com/docs · undatedTake: test first, address at go-live; a return address; docs built from the description.

BigCommerce

Checkout embeds in a frame. In Safari it must be served from the same domain as the storefront. Local tests use a tunnel.

docs.bigcommerce.com … /embedded-checkout/tutorial · undatedTake: a frame only once the address is one. This is why the sheet waits for step B.

oasdiff and llms.txt

A command compares two API descriptions and fails the build on a breaking change. llms.txt is a plain index with a text twin of each page, for agents.

github.com/oasdiff/oasdiff · undated · llmstxt.org · 10 Aug 2026Take: a failing check, not a review habit. Frrata’s snapshot test and llms.txt exist; the gate adds what they miss.

No current source was found for three things. Panel shortcuts in v0, Webflow and Framer. GoKwik’s checkout on code websites. Whether Shopify’s or Stripe’s keys are tied to a domain.

Panels

Chat, preview and inspector. Each side panel folds to a 44 px rail and keeps its place. The rail shows a dot when the agent needs you. A panel never opens by itself. Drag an edge to resize, or use the arrow keys on it. Each person’s layout is remembered on their device.

Keys

[ chat · ] inspector · \ preview only · F6 next panel · 1–4 inspector tab · Ctrl/⌘ K find a page, file or version · ? lists them. Single keys work only outside a text box. One switch turns them off.

A designer’s day

Pick a page, a case and a width. A case shows a real product of the store, like its longest name or a sold-out one. Tap a part to change its words, photo, height or block. Leave a note pinned to a part. Compare two versions side by side. Attach a screenshot or a reference to a message. Words and colours show within seconds.

A developer’s day

Read what each version changed. Read the publish checks with file and line before Publish refuses. Copy one command to work on their own computer. Hand the branch back to the agent. Code is read here. It is written on their computer or by the agent.

Phone

One panel at a time from a bar at the foot: Chat, Site, Design. Code is a computer screen. Checks and Versions stay reachable under Design.

Access

WCAG 2.2 AA for Studio itself. A screen reader can jump to each panel by name. Toggles say open or closed. The resize edge is a slider with a value. The agent’s progress is spoken politely, once a step. Nothing moves under reduced motion.

5 · Rules every app follows, now and later

#RuleWhat fails the build
1An app says what a website gets, in its record: resources, blocks, Frrata-drawn surfaces, or “none” with the reason.check:modules: an app with a shopper file and no site entry.
2A resource is one entry in one table. Its fields are closed. Each field has a description and an example.check:api-docs (new): a field with no description; an example that does not parse against its schema.
3The path list, the reference page, the app’s docs page and llms.txt come from that table. Nobody types them.check:api-docs: a served route missing from the generated description, or the reverse.
4Every block named in a record exists in the starter. The starter’s types match the API.kit.test: a named block with no file; types out of date.
5shop.apps lists what is on. Off means 404 not_available and an empty block. Every way an app stops clears the stored copies at once.A test for each app: on, off, not in plan, paused, trial ended.
6A released version only grows. A change that breaks is a new dated version, with the old kept 12 months.released-api.test (exists) and api-contract-reviewer.
7Every addition writes one line to the API’s “What’s new” page. The line comes from the difference between snapshots.check:api-docs: a snapshot change with no line.
8No cost, no shopper detail and no draft in any resource. Anything personal is Frrata-drawn.check:api and the released snapshot, widened to read every app’s fields from the one table.
