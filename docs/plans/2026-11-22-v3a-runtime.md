## In short
- **Target (owner, 2026-11-22):** Studio working end to end on one test store, Frrata staff only, under a hard spend cap,
  with no credits. Hosting (V2a), credits (C1) and the brand's handover are not built, so the runtime is built against a
  hosting stand-in behind one interface (§ The hosting stand-in), and this plan says what the real one must provide.
- **The first test:** a staff person opens Studio on the test store and types a request. A Managed Agents session runs on
  Starter 0 with the allowed tools. Each tool call runs through `asTurn`. The agent's token and logo changes come back as
  proposals a person applies with `saveBrand`. The result shows in the workbench's Design tab, Console › Brand, checkout
  (P2) and the Storefront API.
- **Model for all testing:** `claude-haiku-5-5`, one constant `STUDIO_MODEL` (owner, 2026-11-22). Spec § 7's model
  returns only for the 20-task proof, on the orchestrator's word.
- **Spend:** list-cost USD caps per turn, per person per day, platform per day and per workspace, all failing closed
  (§ Spend cap). A $25 test is about 100–400 Haiku page turns.
- **Tests never call the live API:** a fake Anthropic server in `e2e/fakes/anthropic.mjs`. Live runs happen later in the
  `frata-studio-eval` environment.

## Binding changes from the spike (workbench plan § The agent spike)
1. The agent file pins `model: {id: STUDIO_MODEL, inference_geo: 'us'}`; `check:studio` checks the pin.
2. The environment is `limited`, `allow_package_managers: false`, `allow_mcp_servers: false`, and `allowed_hosts` is exactly
   the policy's list (`api.frrata.shop` and the media host). `registry.npmjs.org` is never added by the toggle. It goes in
   by name only if the owner allows installs, and the first test does not.
3. The vault credential is `environment_variable` with `injection_location: {header: true}` and `allowed_hosts` exactly
   `['api.frrata.shop']`. `api.frrata.shop` never reflects `Frrata-Key` in a body or an error. R4 adds an API test that
   proves this.
4. `/api/cron/studio` runs every minute as the net, and the open screen's poll may trigger one event read for its own
   session every 5 s. The webhook is a nudge once registered. Every pending `custom_tool_use` of a round is answered in
   **one** `events.send`.
5. The 30-day session sweep is ours (`sessions.delete` 30 days after a session ends), inside the cron.
6. Data is stored in the US; no shopper data or cost reaches the agent (ADR-0003, ADR-0015).

## The first test, step by step (what each piece does and needs)
1. **Who and where.** A staff person signs in as a partner person (passkey), picks the test store in the switcher, and
   opens `/partner/studio`. The store comes from `currentStore()`, never the URL. The page answers only when
   `STUDIO_OPEN=staff`, `staffRole` is set, the person is the partner's owner or Lead on a store linked to that partner,
   and no `studio_switches` row stops it. Otherwise it shows "Studio isn't open yet" (undrawn state 1).
2. **Send (an attempt, ADR-0008).** One server action: Origin checked, Zod (≤ 4,000 characters), the rate limit, then one
   transaction through `withStudio`:
   - the session row on the first message (`runtime_id` null);
   - the turn row with `sent_at`, the partner session id and hash, and its ceiling;
   - the spend reserve (§ Spend cap);
   - the person's line in `studio_messages`.

   After commit, `startOrSend(turn)`:
   - On a new session: mint the 24-hour build key in its own `withStudio` transaction (`mintBuildKey`, purpose `session`),
     create the vault with the key as a `{header:true}` credential for exactly `api.frrata.shop`, upload Starter 0 (a
     tarball of `kit/starter` at a recorded sha256) as a file resource, and create the session with `budget`,
     `vault_ids` and `resources`.
   - Then the budget update and `events.send(user.message)`.

   Any failure after commit deletes that build key and archives the vault, marks the turn failed (`failed_at`, a reason
   code) and returns its reserve. The plain key never touches a row or a log. The person's words reach the model only as
   this `user.message`. Merchant content never does.
3. **Advance.** `advance(session)` lists events after the session's last seen event id (15 s timeout) and stores each
   `agent.custom_tool_use` in `webhook_events`. When the session idles with `requires_action`, it runs every pending call
   through `asTurn` and answers them in one send. At `end_turn` it closes the turn (`ended_at`) and settles spend from
   `usage.list_cost`. At `budget_reached` it closes the turn as paused (`paused_at`) and settles. The agent's
   `agent.message` text becomes one line in `studio_messages`.
4. **Tools** (spec § 4; this slice): `store_facts`, `content_read`, `tokens_propose`, `logo_propose` (SVG checks as spec,
   no text, rasters or filters) and `preview_build`, which the stand-in answers `not_available`. Every read runs as
   `frata_builder` through `withActor` outside any transaction. Every write goes through a turn-keyed definer. Results
   are named fields only.
5. **Apply.** A person's action (never a tool). It reads the proposal under `withStudio` for the current store (not found
   means refused), calls `saveBrand({version, patch})` as that person, then marks the proposal `applied_at` or
   `refused_at` with saveBrand's reason. The Design tab and the preview redraw from the live record. Today's page reads
   are uncached, and `refreshShop` purges the store's `settings` tag.
6. **Seen.** The chat polls `studio_messages` by keyset `(session_id, id)` through a GET route (`private, no-store`),
   backing off as in spec § Design review › Performance. The preview pane shows the console's own store preview of the
   test store (read-only) until hosting exists (undrawn state 7). Code the agent writes in the sandbox is not kept; the
   agent's instructions say so, and its line says what it changed.

## Spend cap (no credits; list cost in USD; fails closed)
| Level | Cap | Enforced by | On reaching it |
|---|---|---|---|
| Turn | $0.50 by default, $1 at most (`TURN_CEILING_USD`) | Before each send the session's `budget.max_list_cost` is set to `spent_so_far + ceiling − max(largest request so far, $0.05)`, rounded down to the cent (spec § 6.7's formula, so the request that crosses it lands inside the ceiling). A session is always created **with** a budget: one can never be added later | Anthropic pauses the session (`budget_reached`); the turn closes as paused; undrawn state 4 |
| Person, per India day | $3 | `studio_spend_days` row `(day, user_id)`, held FOR UPDATE, reserved at Send | Send refused with one line, nothing sent |
| Platform, per India day | $10 | the same table, `(day, null)` | as above; staff told in the line |
| Sessions open at once | 3 | a count under the same lock | as above |
| Workspace | the owner's Anthropic workspace spend limit (Console) | Anthropic | the send fails; the turn fails and returns its reserve |
| Switch | `STUDIO_OPEN` env (`off` default, `staff`) and a `studio_switches` row (one person stops; resuming waits for Admin › Agent) | Send, `advance` and `asTurn` each read it | refused; the cron interrupts open sessions |

- **Reserve and settle.** The reserve is the turn's ceiling. Settling writes `settled_usd = min(reserve, Δ list_cost)` from
  the session's `usage.list_cost` (whole cents; at most 1¢ off, spike). A turn never settled keeps its reserve counted,
  so a dead cron spends nothing more. A failed turn settles at its measured delta (often $0) and returns the rest. No
  tenant row holds a cost (architecture M4): `studio_spend_days` and the per-turn reserve live in a platform-scope,
  definer-only table with no role grant.
- **Fails closed:** a missing key, a missing agent id, a budget that won't set, a reserve that won't write, a switch off, a
  non-staff person or a Builder each refuse the turn before any request leaves.
- **Arithmetic (Haiku 5.5, list, spec § 8's page profile):** 25 requests × (80k read at $0.01/M + 2.4k written at
  $0.125/M + 5k uncached at $0.10/M) + 20k output at $0.50/M ≈ $0.05 a page turn under 100K prompt tokens, ≈ $0.25 above
  it, plus $0.008 of running time. So $0.50 a turn holds a page turn at the higher rate, and $25 is about 100 turns at
  worst. Figures are a guess until the proof measures them (`unit-economics-reviewer`).

## Design review (frata-planning § 3, short; the spec's full review stands)
- **UI/UX:** R6 only, after the undrawn states are drawn. Words follow the redraw. "Frrata agent", "Powered by Claude"
  beneath.
- **Tenancy:** the tenant comes from `currentStore()` for pages and actions, from our open-turn row for tools, and from
  `app_studio_session_for` for events. Never from the model, an event body, a tool input or a URL. Partner policies are
  restrictive. Proof § 91 shows each store and partner reads only its own, and that a later partner or the brand's own
  staff read nothing.
- **Modularity:** pure rules in `src/domains/studio`; the runtime behind `runtime.ts`; tools in `src/lib/studio/tools/`;
  hosting behind `HostingPort`; brand writes only through `saveBrand`.
- **SSOT / DRY:** cost measured once per turn (the `list_cost` delta), the formula once (`spend.ts`), a turn's state from
  timestamps, the brand record's single writer.
- **YAGNI:** no credits, intake, routines, extractor, Admin screen, webhook-as-main-path or patch tool. Each comes back
  with its phase.
- **KISS:** one advance function for three triggers, one budget per session raised each turn, one switch.
- **Scalability:** the test runs 3 sessions at most. At V3b's 70, the cron's `eachLimited(8)` within its deadline is
  re-measured by `speed-reviewer`.
- **Performance:** the poll route runs one keyset select, and its trigger of `advance` is limited per session (5 s). No
  cached loader or read tool runs inside a transaction (`check:studio`). The workbench page stays within its 150 kB
  budget (`scripts/lib/app-budget.mjs`).
- **Reliability:**
  - Send is an attempt row first.
  - Each outbound runtime call follows a committed row and has its clean-up on failure.
  - The event read is idempotent by event id.
  - A tool runs once per `custom_tool_use` id.
  - A dead turn returns its reserve.
- **Security:**
  - Origin checked on actions.
  - Zod caps on every input.
  - Rate limits on Send, Apply and the poll, failing closed.
  - The key goes only into the vault, as a header to one host.
  - Merchant content reaches the model only as tool results marked as data.
  - Logs carry ids and error names only.
  - The fake server refuses a request without the beta header, so tests catch a missing pin.
- **Unit economics:** list cost only, priced at Haiku's higher rate. No price is shown to a partner. The owner's workspace
  limit is the backstop.
- **Storefront API:** no answer changes. One test proves `Frrata-Key` is never reflected (`api-contract-reviewer` on R4's
  test).
- **Blast radius:**
  - `check:capabilities` (a second Actor maker) and `check:actions` (two entry points);
  - `vercel.json` (one cron);
  - `webhook_events` (a new provider);
  - `mintBuildKey` (a new caller);
  - `saveBrand` (a new caller);
  - the workbench shell (moved, with the fixture route kept);
  - ADR-0020 § 5 (an amendment line).
  - Shared files, for the merge plan: `vercel.json`, `scripts/check-capabilities.mjs`, `scripts/check-actions.mjs`,
    `package.json` (scripts), `scripts/verify/tenancy.sql`, `docs/setup.md`, ADR-0020.
