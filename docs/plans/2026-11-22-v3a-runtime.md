## In short
- **Target (owner, 2026-11-22):** Studio working end to end on one test store, Frrata staff only, under a hard spend cap,
  with no credits. Hosting (V2a), credits (C1) and the brand's handover are not built. So the runtime is built against a
  hosting stand-in behind one interface (§ The hosting stand-in), and this plan says what the real one must provide.
- **The first test:** a staff person opens Studio on the test store and types a request. A Managed Agents session runs with
  the allowed tools. Each tool call runs through `asTurn`. The agent's token and logo changes come back as proposals that
  a person applies with `saveBrand`. The result shows in the workbench's Design tab, in Console › Brand, on checkout (P2)
  and in the Storefront API.
- **Model for all testing:** `claude-haiku-5-5`, one constant `STUDIO_MODEL` (owner, 2026-11-22). Every cap is keyed to the
  model, so the proof's model brings its own caps (§ Spend cap).
- **Tests never call the live API:** they run against a fake Anthropic server in `e2e/fakes/anthropic.mjs`. Live runs
  happen later in `frata-studio-eval`.

## Binding changes from the spike (workbench plan § The agent spike)
1. The agent file pins `model: {id: STUDIO_MODEL, effort: 'medium', inference_geo: 'us'}` and has no `multiagent`.
   `check:studio` checks it. At session start the live agent version is compared with the committed file (model, geo,
   tools, network), and a difference refuses the start (architecture, ruling i).
2. The environment is `limited`, `allow_package_managers: false`, `allow_mcp_servers: false`, and `allowed_hosts` is
   exactly `['api.frrata.shop', <the media host>]`. No npm registry is allowed in the first test.
3. The vault credential is `environment_variable` with `injection_location: {header: true}` and `allowed_hosts` exactly
   `['api.frrata.shop']`. R4 adds a test that `Frrata-Key` is never reflected by any Storefront API answer, including
   OPTIONS, TRACE, oversized requests and a wrong `Host:` (security M1).
4. Advancing a session has three triggers. The screen's poll may trigger it (gated in the database, § Advance), the cron
   runs every minute as the net, and the webhook later only nudges. Every pending call of a round is answered in **one**
   send.
5. The 30-day session sweep is ours, in the cron.
6. Data is stored in the US. No shopper data or cost ever reaches the agent.

## The first test, step by step
1. **Who and where.** `requireStudio()` decides on every page, action and route. Otherwise the page shows state 1 of the
   states mockup.
2. **Send** is an attempt (ADR-0008). One server action checks Origin, applies Zod (≤ 4,000 characters) and the rate
   limit, then the spend lock (§ Spend cap). One transaction through `withStudio` writes:
   - the session row on the first message;
   - the turn row and its `studio_turn_keys` row;
   - the person's line.
3. **Start** runs after that commit. Each runtime call follows a committed row (ADR-0006, security H1):
   - mint the build key and write `build_key_id` to the session row in the same transaction;
   - `vaults.create` and the credential, then `vault_id`;
   - Starter 0's file: `git archive` of `kit/starter`, uploaded once per sha256 and its file id reused (speed L1,
     security L5);
   - `sessions.create`, always with `budget` (a budget can never be added later).

   Then the budget raise and `events.send(user.message)`. A failure at any step ends the session (§ Session end) and fails
   the turn with its measured cost.
4. **Advance** (§ Advance) stores each call, runs it through `asTurn` and answers the round in one send. At `end_turn` it
   closes the turn and settles. At `budget_reached` it marks the turn paused and settles. On a session error it fails the
   turn and settles (unit economics F5). The agent's text becomes lines.
5. **Tools in the first test:**
   - `store_facts`: the catalogue only, through `src/lib/queries/builder.ts` as `frata_builder`;
   - `tokens_propose`: values checked with saveBrand's own `Patch` and `brandProblems` before a card renders;
   - `logo_propose`: `cleanSvg` and an outline-only check in `src/domains/brand`, proposed as text, rendered only through
     `<img>`;
   - `preview_build`: the stand-in answers `not_available`.

   Every read runs outside any transaction. Every write is a turn-keyed definer.
6. **Apply** is a person's action under `requireStudio()`:
   - it reads the proposal under `withStudio` for the current store; not found means refused;
   - for a logo, `storeSvgLogo` stores the file, then `saveBrand`;
   - for tokens, `saveBrand({version, patch})`;
   - it marks `applied_at`, or `refused_at` with saveBrand's words (state 9);
   - it is refused on a store with an owner until V3b adds the passkey check (fails closed).
7. **Seen.** The chat polls `studio_messages` by keyset on a `seq` identity column, with an overlap, deduplicated by id
   (speed H1). The preview pane shows the console's store preview (state 7), loaded after the chat. The agent's line says
   what it changed in the sandbox and that the code is not kept.

## Advance (architecture B1, B2, 6; speed H2, H3, M1, M3, M4; security M5; tenancy M)
- **Lease.** `update studio_sessions set advancing_until = now() + interval '90 s' where id = $1 and (advancing_until is
  null or advancing_until < now()) returning id`. No lease means return. Released at the end.
- **Events by cursor.** `events.list` pages behind an opaque cursor. The session row keeps the cursor, and ids already seen
  are skipped. The fake server pages the same way.
- **Calls.** `studio_tool_calls` is unique on `(session_id, tool_use_id)`, partner-locked like every `studio_*` table, and
  holds:
  - the input, capped;
  - `executed_at`, the result and `answered_at`.

  Each call is claimed `FOR UPDATE SKIP LOCKED`. A result is kept until its send succeeds, and a retry sends the stored
  results again. A proposal is unique on its call, so a re-run makes no second copy.
- **Acceptance window** (ADR-0020 § 4). A call runs only if it came after the open turn's `user.message` event and before
  the turn closed. Otherwise it is answered with an error and never runs as the next turn's person.
- **Paused sessions.** At the cap only settle events are accepted, and raising the budget resumes the old work. So the
  next Send raises the budget, sends `user.interrupt`, then the message. Before a turn fails at `requires_action`, its
  pending calls are answered with an error.
- **Timeouts and deadlines.** Each route sets `maxDuration`: the cron 60 s, the poll 10 s, and the poll's `advance` runs in
  `after()`. Inside `advance`: events 5 s, a send 15 s, no retry (the next trigger retries). No step starts that cannot
  finish before the deadline. After answering a round, `advance` keeps reading that session for up to 20 s inside
  `after()`, so a hidden tab doesn't stall a round for a minute.
- **The poll's trigger.** Only while a turn is open and no advance has read in the last 5 s (a column on the session,
  checked in the lease statement, not in an instance's memory). It backs off with the poll (5, 10, 20 s). A platform
  limiter holds 600 Anthropic reads a minute (speed H3: 910 of the 1,200 at V3b's 70 sessions without it). The session is
  resolved under `withStudio`, never from a raw id in the URL.
- **The cron.** It works across tenants only through ids-only definers, executable by `frata_app` only and proved in § 91
  (tenancy H4):
  - `app_studio_due` returns sessions with an open turn, oldest idle first, through a partial index;
  - `app_studio_sweep` returns sessions to end and those 30 days past their end, capped per run.

  The cron also ends sessions whose `app_turn_actor` fails.
- **One `frata_builder` connection per advance.** It is passed down to every read tool (`builderDb`'s React `cache` does
  not hold outside a render: speed M2, architecture 7). R4's deadlock test counts `frata_builder` connections in
  `pg_stat_activity` from a route-handler context.
- **No transaction across a network call.** `check:studio` fails any `runtime.*` call inside a `withTenant`/`withStudio`
  callback.

## Session end (security H1, architecture 5)
- **When a session ends:**
  - on Stop;
  - when `STUDIO_OPEN` is off;
  - after an idle hour (spec § 7);
  - at 23 hours, before its key's 24 run out;
  - when `app_turn_actor` fails (the person, staff row, link or assignment is gone);
  - when its first start fails.
- **What ending does:** sets `ended_at`, deletes the build key, deletes the vault, deletes the session's file reference
  and archives the session. All of it is retried by the cron until done.
- **Thirty days after `ended_at`:** `sessions.delete`.
- **Three open sessions** are counted by `ended_at is null`.

## Spend cap (no credits; list cost; fails closed)
| Level | Haiku 5.5 (`STUDIO_MODEL`) | Enforced by | On reaching it |
|---|---|---|---|
| Turn ceiling | $0.50 (max $1) | Before each send `budget.max_list_cost` = spent so far + ceiling − max(largest request so far, the model's floor $0.12), in cents rounded down. If the largest request ≥ the ceiling, the session ends and the next Send starts a new one (unit economics F8) | Anthropic pauses the session; the turn closes paused (state 4) |
| Person, per India day | $3 | `studio_spend_person (day, user_id)` | Send refused, nothing sent (state 6) |
| Platform, per India day | $10 | `studio_spend_day (day)`, a key with no nulls (unit economics F4, security M2, speed M5, tenancy L) | as above |
| Open sessions | 3 | counted under the platform lock | as above |
| Workspace | the owner's Console spend limit ($25 proposed) | Anthropic | the session errors; `advance` fails the turn and settles |
| Switch | `STUDIO_OPEN` (`off` default, `staff`) | `requireStudio`, `advance`, `asTurn` | refused; the cron ends open sessions |

- **Why $0.50 and not the plan check's $0.25.** By unit economics' check, a Haiku page turn costs $0.058 below 100K prompt
  tokens and $0.258 above (each request in spec § 8's profile is 87.4k tokens). A $0.25 ceiling would pause most page
  turns. The orchestrator's other numbers stand.
- **Locks.** `insert … on conflict do nothing`, then `select … for update`, the person's row then the platform's, last in
  the transaction, with `lock_timeout 2s`. A lock timeout refuses the Send.
- **Reserve and settle.** The reserve is the turn's ceiling, held in its own day's rows (F7).
  - Settling records the **measured** delta of `usage.list_cost` in `MicroUsd`, uncapped, against both day rows (unit
    economics F3, security L3, architecture 4). A turn that overshoots its ceiling by one request is counted as it was.
  - A turn never settled keeps its reserve counted.
  - These tables are platform scope: RLS on, revoked from all seven roles, a restrictive deny-all, written only by
    definers (the `partner_stepups` pattern; tenancy M). Every row is marked `test` (F9).
- **Keyed by model.** `spend.ts` holds a table `{model → ceiling, max, floor, person/day, platform/day}`. `check:studio`
  fails if `STUDIO_MODEL` has no row. The move to the proof's model brings new caps and a raised workspace limit in the
  same change (unit economics F1: on Opus a page turn is $1.13, so these caps would pause every one).
- **Arithmetic (Haiku 5.5, list; spec § 8's profile with 5k uncached a turn).** $0.038 below 100K and $0.190 above for the
  tokens, plus $0.008 of running time. $25 is about 100–500 turns.
- **What Haiku figures cannot price:** credits per page or site, the free credits, turns or tokens per page, cache share,
  success rate or cap sizes. They prove the plumbing, the pause, the cent rounding and Frrata-side failures (unit
  economics). The proof measures tokens, not `list_cost` (whole cents are up to 20% off at 5¢ a turn).

## Design review (frata-planning § 3, short; the spec's full review stands)
- **Tenancy:** the tenant comes from `requireStudio()`'s store for pages and actions, from our open-turn row for tools, and
  from ids-only definers for the cron. Never from the model, an event, a tool input or a URL. Partner locks are
  restrictive and `to public`.
- **Modularity:** pure rules in `src/domains/studio`; the runtime behind `runtime.ts`; tools in `src/lib/studio/tools/`;
  hosting behind `HostingPort`; brand writes only through `saveBrand` and `storeSvgLogo`.
- **SSOT:**
  - vendor cost in `MicroUsd`, measured once per turn;
  - the caps once, by model;
  - a turn's and a session's state from timestamps;
  - the brand record's one writer;
  - text refusals through `lineProblem`.
- **YAGNI:** § Scope's left-out list, each with its signal.
- **KISS:** one advance for three triggers, one lease, one budget per session raised each turn.
- **Scalability:** 3 sessions now. At V3b's 70: the read limiter, the cron's oldest-first order and capped sweep (speed H3,
  M3).
- **Performance:**
  - the keyset on `seq`: 0.09 ms measured;
  - one `frata_builder` connection per advance;
  - the page pinned at 133.4 kB;
  - getting the person's identity with `getClaims()` instead of `getUser()` on the poll is a V3b item (speed L3).
- **Reliability:**
  - Send is an attempt row first;
  - every runtime call follows a committed row and has its clean-up;
  - the cron retries session ends until done;
  - results are kept until sent;
  - a dead turn's reserve stays counted.
- **Security:**
  - `requireStudio()` with the staff passkey;
  - Origin, Zod caps and rate limits failing closed;
  - the key goes only to a vault, as a header to one host, and the vault is deleted at the session's end;
  - the SDK cannot log bodies (`logLevel: 'off'`);
  - merchant content reaches the model only as tool results;
  - agent output renders as text, and a logo only through `<img>`;
  - logs carry ids and error names only.
- **Unit economics:** list cost only, caps by model, nothing billed, test rows marked.
- **Storefront API:** no answer changes; R5 proves `Frrata-Key` is never reflected.
- **Blast radius:**
  - two gates gain entries (`check:capabilities`, `check:actions`), and `check:logs` gains a directory;
  - `mintBuildKey` and `saveBrand` gain a caller each;
  - the workbench shell moves, with the fixture route kept;
  - ADR-0020 § 5 gains an amendment line.
