## Rules this phase holds
- **The tenant id never comes from the browser.** `createMyShop` keeps `requireUser()` (getUser) for the uid and the
  verified email; the partner action keeps `requirePartner()`. The anonymous check reads no tenant and answers one word.
- **The anonymous check never lies.** `checkAddressOpen` answers `ok`, `taken`, `too_short`, `shape`, `reserved` or
  `limited`. Over a limit, or on any database error, it is `limited` (fails closed): the page shows nothing and lets
  the person continue. Creation checks the address again (`slug_taken` → back to the name, everything kept). The
  signed-in `checkAddress` (Settings' rename, the partner's New store) answers `limited` over its limit too, never a
  false "taken".
- **The name lives in sessionStorage only** (key `frrata:signup`: name, slug, slugEdited, arrival time). Never the URL,
  never localStorage, no `next` on `/auth/callback`. A sign-in by the emailed link in a new tab starts at the name.
  What is read back is validated (name a string ≤ 60, slug through `slugProblem`, `arrivedAt` finite and not after now)
  or discarded, and is only ever rendered as text.
- **Definer versions are expand-then-contract.** v3 and the partner's v2 are added and used while v1/v2 still exist
  (0166, applied before the push); v1, v2 and the old partner signature are dropped by 0167, applied only after the new
  build is live (§ Deploy order).
- **No useTransition around an action** (frata-gotchas, Next 15.5): plain pending state, `settle(router)` after.

## Measure ("/start → created")
No existing record fits arrival: the visit beacon is shop-host only and tenant-scoped (A·2), and nothing records
`/start`. The cheapest record without a table: the browser's elapsed time from first arrival (sessionStorage) to
"Create store", clamped by v3 and kept in the `shop.created` audit row's detail (`audit_events`, already read by
Admin as `frata_admin`). The measure is named **/start → created**: it ends at creation, one tap before Home, counts
finishers only, and a sign-in by the emailed link in a new tab restarts the clock. A completion rate needs an arrivals
count that O1 does not record. Admin's read (ad hoc, as `frata_admin`):
`select percentile_cont(0.5) within group (order by (detail->>'signup_ms')::int) from audit_events
where action = 'shop.created' and detail ? 'signup_ms' and at > now() - interval '30 days'` (column name as in
`schema.ts:145`).
