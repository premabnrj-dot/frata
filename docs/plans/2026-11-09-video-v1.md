# Plan: V1 — video on Mux (the foundation; Signal's loops first, reels later)
Status: draft (reviews pending) · Date: 2026-11-09 · Spec: docs/specs/2026-11-09-theme-signal.md § V1 (active) ·

Facts: frata-integrations § Mux (checked 2026-11-09)

## Goal
North star (5) a premium-looking storefront: a short muted loop in a Hero or an Image with text, the way design-led D2C
sites move. Measure: share of Signal shops with a published loop after 30 days; the shop page's LCP unchanged (the poster
is the first paint, never the video).

## What a merchant does (the approved board)
In a Hero or Image with text: **Add a video** (MP4 or MOV, up to 30 s) → **Uploading** (progress, Cancel) → **Getting
it ready** → **Ready** (poster, length, Replace, Remove); **Didn't work** (Choose another). The shop plays it muted, on
loop, only in view, with no sound and no player bar. With no video, the photo shows, as today.

## Design
- **Not a module.** Video is part of the section library, offered only by themes that list it
  (`allowed.sectionVideo`, Signal now; older themes never render it — the T1 narrowing rule). Plan limits: see Unit
  economics (decided by the review).
- **Table `videos`** (per shop): `id`, `tenant_id`, `upload_id`, `asset_id`, `playback_id`, `duration_ms`, `aspect`
  (w/h), `created_at`, `created_by`, `upload_started_at`, `ready_at`, `mp4_ready_at`, `errored_at`, `error` (a code ≤ 40),
  `removed_at`. State is derived from the timestamps (pending → ready → playable; errored; removed). Grant, RLS, policy,
  a tenancy.sql check. Unique `upload_id`, `asset_id`. At most 20 live videos per shop (CHECK in the start action).
- **Start an upload** (`startVideoUpload`, console action, the look editors' roles, support visits refused, rate limited
  per member and per shop, fail closed): ADR-0008 — the `videos` row is committed first (pending), then
  `POST /video/v1/uploads` (fetchWithTimeout) with `cors_origin` = the console origin, `passthrough` = the video row id,
  `new_asset_settings` {playback_policies: public, video_quality: basic, static_renditions: [highest],
  max_resolution_tier: 1080p}, `timeout` 3600; the row gets `upload_id`; the browser receives the upload URL only.
- **The browser uploads straight to Mux** (a `PUT` with progress; files over 64 MB refused before sending; type
  video/mp4 or video/quicktime). Cancel aborts the PUT and marks the row removed.
- **Webhook** `/api/webhooks/mux` (ADR-0006): body ≤ 1 MB, `mux-signature` verified on the raw body (HMAC-SHA256 over
  `t.body`, 5-minute tolerance, constant-time), stored in `webhook_events` under `mux:<environment>:<envelope id>` through
  a definer that maps `passthrough` (our video id) or `asset_id`/`upload_id` to its shop — an event for no row is not
  stored. Answered 200 at once; processed in `after()`: GET the asset from Mux (the source of truth, never the event's
  order), then set `asset_id`, `playback_id`, `duration_ms`, `aspect`, `ready_at`, `mp4_ready_at` (the `highest` static
  rendition ready), or `errored_at` + code. Over 30 s on ready: `errored_at` 'too_long' and the asset deleted.
- **Remove** (and Replace's old video): `removed_at` now, and an outbox `mux.asset.delete` in the same transaction
  (drained at once; 404 = done). A published look that still points at a removed video shows the photo (never a
  broken player).
- **The section** stores `video: { id } | null` (a uuid; checked to be the shop's own at save). The shop's cached read
  carries the shop's playable videos (id → playback id, aspect; ≤ 20 rows, a few hundred bytes); saving or a webhook
  that changes a video revalidates the shop's tag.
- **The shop plays** `<video muted loop playsinline preload="none" poster="https://image.mux.com/{pid}/thumbnail.webp?width=…">`
  with `src` = `https://stream.mux.com/{pid}/highest.mp4` set by one shared island only when the section is in view
  (IntersectionObserver), paused out of view; `prefers-reduced-motion`: the poster only. No player script.
- **CSP**: the shop adds `media-src https://stream.mux.com` and `img-src https://image.mux.com`; the console adds
  `connect-src` for the upload host Mux returns (read from the first real upload URL in the development environment and
  pinned; until then the fake Mux's host in e2e).
- **Environments**: `MUX_TOKEN_ID`, `MUX_TOKEN_SECRET`, `MUX_WEBHOOK_SECRET` (Production, Sensitive; a Development
  environment's set in Preview); absent → the video field says video isn't switched on, nothing calls Mux. e2e: a fake
  Mux in `e2e/fakes/` (uploads, assets, delete, a signed webhook back to the app).
