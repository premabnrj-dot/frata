## Goal
North star (5): a premium storefront built as code by partners. SA1 lets a site **read** a shop; SA1b lets it **sell**:
a shopper's bag on the brand's site becomes an order on Frrata's checkout, credited to the site, and the shop's own
Frrata pages hand shoppers to the site. Plus what a partner needs to start (the starter, the skill, the docs) and what
Frrata staff need to see (Admin › Storefront API).
Measures: the spec's 90-day measures start here (≥ 3 partner sites live; orders whose source is "Your website";
handoff → order rate). Phase gates: e2e `9x-storefront-sale` green (site bag → cart link → order → source "Your
website"); a hidden page previews on a site only with a valid token (int test: tampered, expired, other key, other
entry, other shop → one 404); the starter builds against the e2e stack in CI, blocking; **zero** cross-shop reads,
**zero** cost fields (the SA1 gates extended to every new resource and the docs' examples).

## Tasks

### D·1 The cart link (no server write)
- `src/domains/storefront-api/cart-link.ts` (pure): `parseCartLink(search) → { lines: {variantId, qty}[], code? } | null`
  — `l=<uuid>:<1–10>,…`, ≤ 20 lines (the bag's own `MAX_LINES`, `MAX_QTY`), duplicate ids summed and capped, anything
  else null; `code` the bag's existing offer-code shape. `cartLink(checkoutHost, lines, utm?)` for the docs and the
  starter (one builder, tested both ways).
- Page `src/app/s/[host]/(checkout)/cart/page.tsx`: an ISR shell (`revalidate 60`, `force-static`, `noindex`), no
  shop data beyond the frame; a client island `cart-link.tsx` runs `captureAttribution()` first (the tab's first page:
  its referrer is the site, its `utm_*` the site forwarded), then `parseCartLink(location.search)` → **replaces** the bag
  (`bag.replace`, new: the site's bag is the whole truth; an old Frrata bag would add stale lines) → `offerCode.set` →
  `location.replace('/checkout')`. A link that doesn't parse shows the one state drawn ("This bag link doesn't work" ·
  "Go to the shop" → the site's origin when it runs elsewhere, else `/`). Unknown or other shops' ids drop at checkout
  as today (the quote resolves variants inside the host's shop; "changed" words).
- The cart link is `(checkout)`, so it never moves to the site (D·2). `[...rest]` and the WAF are untouched (shop host).
- Verify: `npx vitest run src/domains/storefront-api` (shape, caps, duplicates, `javascript:`/`%00`/extra params
  ignored, 21 lines refused); e2e step (below).

### D·2 The shop's Frrata pages move to the site (spec § 4 "Redirects"; owner question 2)
- **Measured first** (`next start`, Next 15.5): `redirect()` in an ISR page is cached with status 307 and a fixed
  `Location`, but a cached page can't read the query, so a shopper's `?utm_source=instagram&code=…` is lost on the move
  (the reason today's old-name move, `MovedTo`, is a client move: shop addresses D·1). Recorded in `frata-gotchas`.
- **Built:** `StoreShop` gains `siteOrigin: string | null` (from `shop_settings.site_origin`, a public fact; the shop
  entry grows by one string). `src/app/s/[host]/(shop)/layout.tsx` wraps its children in the existing `MovedTo` with
  `to = siteOrigin` when the store is **open** and runs elsewhere (owner question 2b). `movedUrl` gains a path filter
  `SITE_PATHS` (pure, `src/domains/addresses/names.ts`): only `/`, `/products/<handle>`, `/collections/<handle>`
  move; the bag, checkout, `/cart`, orders, policies and `/pages/*` stay. The target keeps the path, query and
  fragment; leading `/` and `\` are stripped and the result's origin re-checked equal to `siteOrigin` (spec § 4).
  The page carries `<link rel="canonical">` to the site URL. Switching back to Frrata stops the move at the next copy.
- **Freshness:** `setWebsite` now purges `refreshShop(t, 'shop')` as well as `refreshKeys(t)` (rare, owner-only);
  `openShop` already purges the shop. A domain removed (the trigger clears the origin, no console write) is already in
  `app_shops_with_key_stop`; the drain adds `refreshShop(t, 'shop')` beside `refreshKeys(t)` for those shops.
- `sitemap.xml` on a shop that runs elsewhere lists only `/pages/*` and policies (the moved paths belong to the site's
  own sitemap).
- Verify: `names.test.ts` (each path kind, `//evil.com`, `/\evil.com`, `%2F%2F`, query and hash kept, origin re-check);
  e2e step; `05-shop-look` pixel unchanged for a shop on Frrata.

### D·3 "Your website" as a source (spec § 4 "Attribution")

### D·4 The signed preview token (ADR-0018 § 12; owner 2026-11-15)
- **Why a path of its own:** a hidden page must also preview **after the store opens**, when no test key is left
  (test keys end at opening). So the token rides with **either** key kind on a dynamic path:
  `/2026-12/k/<key>/preview/<token>/pages/<handle>` and `…/preview/<token>/faq`, rewritten (next.config `apiRewrites`,
  before the key-kind rules) to `/api/storefront/2026-12/p/[key]/[token]/{pages/[handle],faq}` — a third tree `p/`
  (`force-dynamic`, `private, no-store`, never ISR or `shopCached`; `check:api` gains the tree's rules).
- **Token** (`src/lib/storefront-api/preview-token.ts`, server only; pure parts in `src/domains/storefront-api/preview.ts`):
  `v1.<base64url(payload)>.<base64url(HMAC-SHA256)>`, payload `{ t: tenantId, k: keyId, e: 'page:<handle>' | 'faq',
  x: expiry (unix s) }`, expiry ≤ now + 600 s, compared with `timingSafeEqual`; ≤ 400 chars (the WAF path rule gains
  `preview/v1\.[A-Za-z0-9_-]{20,300}\.[A-Za-z0-9_-]{43}/(faq|pages/[a-z0-9-]{1,100})`). Secret
  `STOREFRONT_PREVIEW_SECRET` (32 bytes, Vercel, owner step in `docs/setup.md`); unset → previews are refused (fail
  closed) and the console hides the button.
- **apiRequest** (`tree: 'preview'`): key shape → `storefrontKeyFor` (either kind: the definer's stops all apply) →
  `apiPreviewIp` limit (new `LIMITS` row, 30 a minute per `ipBucket`, fails closed) → the token: signature, `t =
  ctx.tenantId`, `k = ctx.keyId`, `e` = this resource and handle, `x > now` — any miss is the one 404 body. CORS as the
  test tree (the site origin or `http://localhost:<port>`). The handler reads `previewPages(ctx.tenantId)` (hidden and
  unpublished drafts included) through the same `storePageOut`/`faqOut` mappers; nothing else opens. Logs `[api]
  preview <code> key=<keyId>`, never the token.
- **Minting** (`src/app/(console)/console/content/actions.ts`, `previewOnWebsiteAction({ entry, keyId? })`):
  `asMember(CAN_BUILD, …)` then the content capability lane B's writes use, refused in a support visit; the key must be
  this shop's live (not deleted, not expired) row, read `where id and tenant_id`; one key → used, more → the person
  chose it in the dialog (owner question 6); `audit_events` `content.preview` (target the entry, detail the key id).
  Returns `{ url: <site origin>/frrata-preview?token=…&to=/pages/<handle> }` once (never stored, never in a toast).
  The starter's `/frrata-preview` route turns on its draft mode for 10 minutes and reads through the preview path.
- Verify: `preview.test.ts` (round trip; each field tampered; 601 s refused; another entry; base64 padding and length
  edge cases); int test (A's token under B's key → 404; a live key after the store opened previews a hidden page;
  revoked key → 404; a live key without a token still never reads a hidden page); `check:api` caught a planted `p/`
  route with `revalidate`.

### D·5 The slim index: search and D2 filters
- `apiIndex = shopCached('index-v1', 'catalogue', …, 3600)` in `src/lib/queries/storefront.ts` (or a sibling file if
  the size gate says so): per listed product ~150 B — id, handle, title, tags, price range (paise), sizes in stock,
  colour families, collection ids, first photo key, the shop's order. Built from the catalogue core, not a second query
  path. Bytes measured at the 10× seed (≈ 90 kB at 600) and asserted ≤ 256 kB at 1,500 in a size test.
- `search` reads `apiIndex` (was the 880 kB catalogue entry; speed M2); the answer is unchanged (released snapshot).
- **D2** `filter/page/{n}?collection=&size=&colour=&price=&stock=&sort=` — a new resource, dynamic live route like
  search (`public, s-maxage=60`, `apiSearchIp`), canonical parameters only: each once, values from the shop's own index
  (unknown → `400 {"error":"bad_filter"}` after the key checks out), price as fixed bands
  (`0-999`, `1000-1999`, `2000-4999`, `5000-`), sort `featured|new|price-asc|price-desc`; 48 a page, `total`,
  `truncated` at 600 as `products/page`. Cards for the page's ids come from the same cached catalogue entry the page
  routes read (no new loader). `filters` (ISR, hour) answers the shop's facets with counts so a site draws its menu.
  Both additive to `2026-12` (new resources; the released snapshot grows).
- Test keys: the same two on `t/` over the preview catalogue.
- Verify: `map.test.ts` (filters: each facet, an unknown value, two of one facet, bands, sorts, a listed-only check:
  a hidden product never counted in a facet); `released-api.test.ts` grows; `waf.test.ts` (new paths in, a query never
  in the path rule); `SPEED=1` bytes and timings.

## Design review (frata-planning § 3)
- **UI/UX.** Screens: `/cart` (shopper: one transient state, one error), the handover block, Content › Pages' Preview on
  website (button + key choice dialog + "Copy link"), Settings › Website's Docs and Starter links, Admin › Storefront
  API (band, list, record, Versions, empty, error, phone), the docs pages (home, a guide, a reference page, phone).
  Rule 0 on all; Admin by the owner's Admin rules (one job, waiting task first, More menu, no help text). States drawn
  in the mockup. Keyboard: the Preview dialog is the console `Dialog`; the docs are plain links and headings.
- **Tenancy.** Tenant sources unchanged: the cart link names variants, never a shop (the host does; the quote resolves
  inside it); the preview token is checked **against** `ctx.tenantId` from the key, never a source of one; the
  handover definer derives the tenant from the invite and the caller's uid; Admin reads only through `frata_admin` and
  an aggregate definer. No new table. `tenancy-auditor` on this plan.
- **Modularity.** Pure: `cart-link.ts`, `preview.ts`, `SITE_PATHS`, the classifier rule, the filter parser. I/O:
  `preview-token.ts`, `queries/storefront-api.ts` (`siteHostIn`), `admin/storefront-api.ts`, `db/partners.ts`. The kit
  is outside `src/` and imports nothing from it.
- **SSOT / DRY.** The site origin stays one fact (`shop_settings.site_origin`): CORS, the move, the source rule, the
  handover block and Admin read it. The cart-link format: one builder, copied to the starter by a build step and held
  equal by a test. The source: one classifier, derived on read. The index derives from the catalogue core.
- **YAGNI.** Out: D3 past 600, the module contract (owner question 5), a pause in Admin (7), a usage panel, a typed
  client, a docs site of its own (the docs are static pages on the API host), product previews by token (a test key
  already reads draft products; signal: a brand asks to preview a hidden product on an open site).
- **KISS.** The move reuses `MovedTo`; the cart link writes the existing bag; the token is one HMAC; the sweeps page
  inside the run instead of a stored cursor (signal for one: the budget log line in Observability).
- **Scalability.** Sweeps: 500 a page × pages within 20 s (≈ 10,000 shops a run at 4 at a time); the reinstatement
  union reads a partial index. The index entry ≈ 150 B × listed products. Admin's definer: one grouped scan of
  `storefront_keys` (≤ 20 live keys a shop) joined to `shop_settings` and `tenants` — EXPLAIN at the 10× seed with 500
  shops before build.
- **Performance and speed.** (a) `/cart`: static shell, no read. A shop page: one string more in the cached shop entry,
  no statement. Analytics and the order page: one more column read in their existing transaction. (b) EXPLAIN: the
  three sweep definers with `p_after`, the reinstatement union, `admin_storefront_api_shops`, `app_handover_keys`.
  (c) `index-v1` ≤ 256 kB at 1,500 listed. (d) no shop HTML grows beyond the canonical link. (e) `setWebsite` purges
  the shop scope (rare). (f) the cart island ≤ 3 kB gz on the checkout surface. (g) nothing new preloaded.
  `speed-reviewer` on this plan.
- **Reliability.** Nothing outbound. The preview secret unset fails closed. The drain's sweeps fail per sweep (logged),
  never the outbox.
- **Security.** The cart link: no write, closed shape, bag replaced only from the link's own lines, `location.replace`
  only to the same origin's `/checkout`. The move: origin re-checked (no open redirect), only when the store is open.
  The token: HMAC, ≤ 10 min, bound to tenant, key id and entry, its own per-network limit, `no-store`; it rides in the
  path, so Vercel's request logs hold it for its ten minutes (noted, like keys). The handover block: names and prefixes
  only, to the invitee. Admin: aggregates, no key material. Docs: static, no input. `security-reviewer` on this plan.
- **Motion and visuals.** The Preview dialog and Admin's sheets use the console's Dialog/Sheet motion; nothing new.
  Admin's band reuses the redraw's `band`.
- **Unit economics.** No price, fee or plan changes; the new cost is the docs' CDN hits (static) and the filter route
  (a dynamic CDN-cached read per distinct query, under `apiSearchIp`). Not run: no money moves (orchestrator brief).
- **Storefront API.** Additive to `2026-12`: `filters`, `filter/page/{n}`, the preview paths; the snapshot grows; no
  field removed; no cost, shopper or draft field reaches a live-key answer (a hidden page only behind a valid token).
  Purges: `filters`/`filter` by the catalogue tag; preview never cached. `api-contract-reviewer` on this plan.
- **Blast radius.** `classifySource`'s four callers; the shop layout (`(shop)/layout.tsx`); `bag-store.ts` (`replace`);
  `apiRewrites`, `host.ts`, the middleware matcher; `request.ts` (a third tree); the drain; `/handover`; Admin's nav;
  `check:api`, `check:tenant` (§ 9 covers `p/`), `ops/firewall.json`; CI (the starter job).
