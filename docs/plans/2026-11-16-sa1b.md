## Goal
North star (5): a premium storefront built as code by partners. SA1 lets a site **read** a shop; SA1b lets it **sell**:
a shopper's bag on the brand's site becomes an order on Frrata's checkout, credited to the site, and the shop's own
Frrata pages hand shoppers to the site. Plus what a partner needs to start (the starter, the skill, the docs) and what
Frrata staff need to see (Admin › Storefront API).
Measures: the spec's 90-day measures start here (≥ 3 partner sites live; orders whose source is "Your website";
handoff → order rate). Phase gates: e2e `9x-storefront-sale` green (site bag → cart link → order → source "Your
website"); a hidden page previews on a site only with a valid token (int test: tampered, expired, other key, other
entry, other shop → one 404); the starter builds against the e2e stack in CI, blocking; **zero** cross-shop reads,
**zero** cost fields (the SA1 gates extended to every new resource and the docs' examples).

## Tasks

### D·1 The cart link (no server write)
- `src/domains/storefront-api/cart-link.ts` (pure): `parseCartLink(search) → { lines: {variantId, qty}[] } | null`
  — `l=<uuid>:<qty>,…`; the limits come from the quote (`src/domains/checkout/quote.ts`, not the bag's own copies):
  ≤ 20 lines (the spec's 50 is amended to 20 in the same commit), a quantity over 10 **clamped** like the quote does,
  duplicate ids summed then clamped; a percent-encoded `:` or `,` and upper-case uuids accepted; anything else in `l`
  → null. `cartLink(checkoutHost, lines, params?)` for the docs and the starter (one builder, tested both ways).
- **The bag link is a published contract with a frozen grammar** (contract M5): the URL has no version, so `l` never
  changes meaning; anything new is a new parameter. Honoured: `l`, `code` (the offer-code shape the bag already
  takes), `utm_*`, and the click ids `captureAttribution` already reads (`gclid`, `gbraid`, `wbraid`, `fbclid`,
  `srsltid`) as stronger evidence; everything else is ignored. Documented: before the store opens it lands on checkout's
  own "opening soon"; while paused, checkout's pause; a deleted size drops at checkout with "changed". `Shop` gains
  `cart { url, maxLines, maxQty }` (additive).
- Page `src/app/s/[host]/(cart)/cart/page.tsx` with a **bare layout** (outside `(checkout)`, whose frame reads the
  shop, look, content, offer bar and catalogue for a page seen under a second; speed 7): an ISR shell (`revalidate 60`,
  `force-static`, `noindex`), one cached shop read (name, site origin); a client island `cart-link.tsx` runs `captureAttribution()` first (the tab's first page:
  its referrer is the site, its `utm_*` the site forwarded), then `parseCartLink(location.search)` → **replaces** the bag
  (`bag.replace`, new: the site's bag is the whole truth) **only when the referrer is the site's origin or the bag is
  empty; otherwise the link's lines merge in** (security L1: any site could otherwise wipe a shopper's bag) → the code
  is left to `captureAttribution` (it already records `?code=` as a link, so a leaked code still trips the leak alert;
  security M6) →
  `location.replace('/checkout')`. A link that doesn't parse shows the one state drawn ("This bag link doesn't work" ·
  "Go to the shop" → the site's origin when it runs elsewhere, else `/`). Unknown or other shops' ids drop at checkout
  as today (the quote resolves variants inside the host's shop; "changed" words).
- `/cart` is outside `(shop)`, so it never moves to the site (D·2). `[...rest]` and the WAF are untouched (shop host).
- Verify: `npx vitest run src/domains/storefront-api` (shape, caps, duplicates, `javascript:`/`%00`/extra params
  ignored, 21 lines refused); e2e step (below).

### D·2 The shop's Frrata pages move to the site (spec § 4 "Redirects"; owner question 2)
- **Measured first** (`next start`, Next 15.5): `redirect()` in an ISR page is cached with status 307 and a fixed
  `Location`, but a cached page can't read the query, so a shopper's `?utm_source=instagram&code=…` is lost on the move
  (the reason today's old-name move, `MovedTo`, is a client move: shop addresses D·1). Recorded in `frata-gotchas`.
- **Built:** `StoreShop` gains `siteOrigin: string | null` (read once: `RESOURCES.shop` then takes it from the shop
  entry instead of its own `siteOriginFor`, so the answer and the move never disagree; contract minor 8) (from `shop_settings.site_origin`, a public fact; the shop
  entry grows by one string). `src/app/s/[host]/(shop)/layout.tsx` wraps its children in the existing `MovedTo` with
  `to = siteOrigin` when the store is **open** and runs elsewhere (owner question 2b), through a **separate** pure
  `siteUrl(origin, loc)` in `src/domains/addresses/names.ts` (`movedUrl` is untouched: it takes a host, and the
  old-name move must keep covering `/bag`; security M5): only `SITE_PATHS` (`/`, `/products/<handle>`,
  `/collections/<handle>`) move; the bag, checkout, `/cart`, orders, policies and `/pages/*` stay. Every leading `/`
  and `\` collapses to one `/`; the scheme comes from the origin; `new URL(path + search + hash, origin)` must have
  `url.origin === origin` and `url.host !== loc.host` (a site address Frrata itself still serves would reload forever).
  `MovedTo` takes the built URL rather than building it.
- **No loop** (architecture 1): no move when the current host is the site host or its `www.`/apex twin (while the
  site's DNS still points at Frrata, the shop serves that host), and a one-hop marker in `sessionStorage` stops a second
  move in the same tab. `names.test.ts` has a case for each.
- **Every navigation, before paint** (architecture 3, 4): a small inline script in the shop head (no `script-src` in the
  storefront CSP) runs the same pure path filter before paint, so the theme page never paints and the visit beacon is
  skipped when moving; the effect stays for soft navigation and depends on `usePathname()` (a layout doesn't remount).
  Rejected: a host lookup in the middleware on every shop request (a paid run per CDN hit).
- **Canonical, og:url and JSON-LD** follow the site URL (`src/domains/seo/tags.ts` `shopTags`, `_meta.ts`).
  The page carries `<link rel="canonical">` to the site URL. Switching back to Frrata stops the move at the next copy.
- **Freshness** (speed 3: `shop:<t>` is on every entry, so purging it rebuilds the catalogue): the shop entry gains
  its own tag `shop:<t>:settings`; `setWebsite` purges that tag and `refreshKeys(t)`; `shop-v2` → `shop-v3` and
  `api-shop-v1` → `v2` (the shape grows; an hour-long entry outlives a deploy). `request.ts` and `RESOURCES.shop` read
  `siteOrigin` from the cached shop entry, dropping an uncached `siteOriginFor` per test request (speed 9);
  `openShop` already purges the shop. A domain removed (the trigger clears the origin, no console write) is already in
  `app_shops_with_key_stop`, which now returns `(tenant_id, moved boolean)`: only rows from the domain arm purge
  `shop:<t>:settings`; a partner suspended at a drop purges keys only, never the catalogue (speed 3).
- `sitemap.xml` on a shop that runs elsewhere lists only `/pages/*` and policies (the moved paths belong to the site's
  own sitemap).
- Verify: `names.test.ts` (each path kind, `//evil.com`, `/\evil.com`, `%2F%2F`, query and hash kept, origin re-check);
  e2e step; `05-shop-look` pixel unchanged for a shop on Frrata.

### D·4 The signed preview token (ADR-0018 § 12; owner 2026-11-15)
- **Why both key kinds:** a hidden page must also preview **after the store opens**, when no test key is left (test
  keys end at opening). **The token rides in a header, not the path** (architecture 12): `GET
  /2026-12/k/<key>/preview/pages/<handle>` and `…/preview/faq` with `Frrata-Preview: <token>`, a dynamic route inside
  **both** existing trees (`k/[key]/preview/…` and `t/[key]/preview/…`, like search is a dynamic route inside `k/`):
  no third rewrite, no token regex in the WAF (the path rule gains only `preview/(faq|pages/[a-z0-9-]{1,60})`), and the
  token never reaches Vercel's request logs. A site's server sends it (server to server: no preflight, no CORS).
  `force-dynamic`, `private, no-store`, never ISR or `shopCached`; `check:api` names these routes. ADR-0018 gains an
  amendment line on § 11 ("drafts never" → "never without § 12's token") and skill rule 5 the same.
- **Token** (`src/lib/storefront-api/preview-token.ts`, server only; pure parts in `src/domains/storefront-api/preview.ts`):
  `v1.<base64url(payload)>.<base64url(HMAC-SHA256)>`, payload `{ e: 'page:<handle>' | 'faq',
  x: expiry (unix s) }` only; the tenant id and key id go into the MAC input, never the payload (contract minor 3:
  shorter, and nothing in clear in partner URLs or logs), expiry ≤ now + 600 s, compared with `timingSafeEqual`; ≤ 400 chars. Secret
  `STOREFRONT_PREVIEW_SECRET` (32 bytes, Vercel, owner step in `docs/setup.md`); unset → previews are refused (fail
  closed) and the console hides the button.
- **apiRequest** (`mode: 'preview'` in either tree, **its own branch**, never the "not test" one: `private, no-store`, never CORS `*`,
  either key kind accepted at the kind/tree check, no `markKeySeen`; an int test asserts a live-key preview's headers;
  tenancy audit HIGH 2): key shape → the definer **uncached** (`storefrontKeyRow`, so a stop applies at once rather
  than at the next drain; the tree is dynamic and limited; tenancy MEDIUM; `check:tenant` § 9 lets `request.ts` call
  it for this tree only) (either kind: the definer's stops all apply) →
  `apiPreviewKey` limit (new `LIMITS` row, 30 a minute per key (security review on the diff: sites share outbound addresses), fails closed) → the token: signature, the MAC over
  `ctx.tenantId` and `ctx.keyId`, `e` = this resource and handle, `x > now` — any miss is the one 404 body. No CORS header (the
  starter reads previews on its server; security L2). The handler reads `previewPages(ctx.tenantId)` (hidden and
  unpublished drafts included) through the same `storePageOut`/`faqOut` mappers, the cached shop read only after that transaction closes (P4;
  speed 12); nothing else opens. Logs `[api]
  preview <code> key=<keyId>`, never the token.
- **Verifier, exactly** (security M2, M3, L2, L4, L6): the MAC input is `frrata-preview-v1.` + the payload segment;
  the expected signature string is recomputed and compared with `timingSafeEqual` **after a length check** (a length
  mismatch is the 404, never a throw); the MAC is checked before `JSON.parse`, then the payload through a strict Zod
  object; the verifier itself refuses `x > now + 600` as well as `x ≤ now`. The secret is Sensitive, **Production
  only**, read through `secret()` (`src/lib/env.ts`), and refused under 32 decoded bytes (a preview deployment can't
  mint tokens production accepts); rotating it ends every live token (`docs/setup.md`). Preview routes send **no CORS
  header** (the starter reads previews on its server). Handle caps match the live rule (60). `preview.test.ts` asserts
  the path's headroom under the WAF cap. The payload carries only the entry and expiry; the tenant and key are
  bound inside the MAC.
- **Minting** (`src/app/(console)/console/content/actions.ts`, `previewOnWebsiteAction({ entry, keyId? })`, through
  content's own `write()` door: the support refusal, the `contentSave` limit and `memberAudit` come with it; Zod
  `strictObject({ entry: /^(faq|page:[a-z0-9-]{1,60})$/, keyId: z.uuid().optional() })`; the answer is the URL only;
  security L3):
  `asMember(CAN_BUILD, …)` then the content capability lane B's writes use, refused in a support visit; the key must be
  this shop's live (not deleted, not expired) row, read `where id and tenant_id`; one key → used, more → the person
  chose it in the dialog (owner question 6); `audit_events` `content.preview` (target the entry, detail the key id).
  Returns `{ url: <site origin>/frrata-preview?token=…&to=/pages/<handle> }` once (never stored, never in a toast).
  The starter's `/frrata-preview` route turns on its draft mode for 10 minutes and reads through the preview path.
- Verify: `preview.test.ts` (round trip; each field tampered; 601 s refused; another entry; base64 padding and length
  edge cases); int test (A's token under B's key → 404; a live key after the store opened previews a hidden page;
  revoked key → 404; a live key without a token still never reads a hidden page); `check:api` caught a planted `preview/`

### D·5 D2 filters; the slim search entry not built (after the contract, architecture and speed reviews)
- **No slim index** (owner question 9). Every search hit and filter card is a full `cardOut` card, which needs each
  size's stock facts, the offer badge, the struck price and the colours; an index holding all that is the catalogue
  entry again (measured: ≈ 360 kB at 1,500 products even without them, over its own gate). So search and filters
  read the hour-long catalogue entry they already read, matching and counting in memory (measured: 5.5 ms to parse and
  expand a 1.1 MB entry). Signal to revisit: search or filter p95 over 50 ms in Observability. Search's answer is
  untouched (no change to the released resource).
- **D2** `filter/page/{n}?collection=&size=&colour=&price=&stock=&sort=`: a new resource, its own `FilterPage`
  schema; a dynamic live route like search (`public, s-maxage=60`, `apiSearchIp`); `filter/page/{n}` rather than a
  query on `products/page` because that route is a cached copy that can't read the query.
  - **One URL per filter** (speed 8): parameters in a fixed order (`collection, size, colour, price, stock, sort`)
    and defaults left out (`sort=featured`); any other order or a default spelled out is a grammar error (400), so the
    CDN keeps one copy per filter, not one per spelling.
  - **Two kinds of miss** (contract M1): a grammar error (an unknown parameter, one twice, a malformed value, an
    unknown `sort`, `price` or `stock` value) answers `400 {"error":"bad_filter","param":"<name>"}` after the key
    checks out; a well-formed size, colour or collection the shop doesn't have now answers **200 with `total: 0`**
    (stock comes and goes; an hour-old menu link must not break a site). `apiRequest` gains one typed refusal for
    this (`run` may return `{ refuse: 'bad_filter', param }`); skill rule 3 notes the exception; `err()` in
    `openapi.ts` gains the `param` field.
  - **Meanings fixed in `.describe()`** (contract M3, M4): `collection` is a handle, resolved as
    `RESOURCES.collection` does (moved handles followed), members by `inCollection(c, listed, now)` per request;
    `size` is any value of an option the merchant named Size (case-folded), `colour` a colour family's slug, each as
    the `facets` answer gives its `value`; `price` a band id from `facets` (`{ id, min, max }` in paise, half-open,
    over `priceOf().min`, a live offer not counted; ids are an open enum); `stock=in` keeps in-stock and low (not
    pre-order, not made to order); `sort` `featured|new|price_asc|price_desc` (snake_case like every enum),
    `featured` meaning the collection's own order when `collection` is given, else the shop's; `total` counts the
    filtered set within the 600 cap and `truncated` says the cap cut the catalogue. `,` is reserved inside values
    for multi-select later.
  - **`facets`** (renamed from `filters`, one letter from `filter`; ISR, the hour, `shopCached` on the catalogue tag so
    `refreshSoldOut` and the boundary sweep reach it): each facet's values with the exact `value` to send and a count
    over the same capped, listed set as the pages.
  - Both additive to `2026-12`.
- Test keys: the same two on `t/`, **listed only** like lists and search today (a facet count never shows a draft's
  sizes or colours: a test).
- **The released snapshot** (contract B3): first run `released-api.test.ts` green against today's file; then
  `UPDATE_API=1` refuses to write when `narrowed(old, new)` finds anything; `Facets`/`FilterPage` join its
  `RESOURCES`; `git diff` of `__tests__/released/2026-12.json` must only add keys and change descriptions.
- **`openapi.ts`** (contract M6): `facets`, `filter/page/{n}` with each query parameter's values and the 400, the two
  preview paths with the `token` segment (a token miss described as the same 404); the info line about drafts
  restated (pages and the FAQ need the token under either key); `Shop.checkoutOrigin`'s "coming next" and the "cart
  link comes in the next release" line replaced by the bag link's rule; `check-api.mjs` names filter beside search as
  the dynamic live routes.
- Verify: `map.test.ts` (each facet, an unknown parameter → 400, an unknown size → 200 empty, two of one parameter,
  out-of-order → 400, bands, sorts, collection rules, listed-only counts); `released-api.test.ts`; `waf.test.ts`
  (`facets|filter/page/([1-9]|1[0-3])` in, a query never in the path rule); `SPEED=1` bytes and timings.
