# Feedback: toasts, popups, field errors — plan
Status: active · Spec: `docs/specs/2026-11-12-feedback.md` · Mockup: https://claude.ai/artifact/J74M3yUytfbgkMh4UNQbcp ·
Approved: owner, 2026-11-12 ("approved, go ahead with all four steps") · Rules: `frata-design-language` § Feedback (5.21.0)

Four phases, each shipped on its own (push to `main` after its gates). Every task ends with `npm test`, `npm run
typecheck`, the e2e flows it touches, and `impact-reviewer` on its diff.

## Reviews on this plan (2026-11-12) and what changed
Architecture (CHANGES NEEDED) and security (FIX BEFORE MERGE) ran after F0 had started on the branch (nothing on
`main`); every finding is folded in here and in the code before F0 ships:
- **No flash cookie** (security MED-1/3, LOW-1–3; architecture KISS): actions return `{ ok, error, fields, go }` to an
  `<ActionForm>`; no result in a URL or cookie; the shop never reads one.
- **Mount point**: AppShell mounts the Toaster (inside `[data-shell]`, outside `main`), `calm` in Admin (no snap,
  rule 22), `--toast-lift` above the phone's bottom bar; the passkey gate has its own; public marketing pages none
  (rule 44: /partners, EkCode's static pages); the shop's is a small storefront component in F3 (byte budget, no
  `cn`, `shop.css` sources), with `--store-bar` set by the pay bar.
- **Screen readers**: a page without the shell gets the Toaster's polite region; a toast raised while a Dialog is open
  is drawn inside it; the field summary is quiet (no re-alert per count), focus goes to the field.
- **Lifetime**: error toasts leave on a page change; a form's summary leaves when the form unmounts; Show keeps it.
- **Field errors**: `scope` (the form) is required; a closed `<details>` opens; inside a Dialog no toast. F1 maps
  error keys to field names where they differ (variant grid `v:k:f`, checkout `address.*`).
- **Gate**: whole-file JSX, dynamic `role={…'alert'}`, `<div role="alert">`, `<Message>`, `?ok=`/`sp.ok`, the
  shop's `text-store-bad`; pinned sites carry `feedback-ok: <why>` on the line (no file-level pass): 304 lines.
- Minor: type-scale classes; e2e readers of `getByRole('alert')` are 48-themes-v4, 72-designs, 75-staff-passkeys;
  the board's flow is 30-primitives; timer tests live in e2e (no DOM test environment).

## Regression net (before F0)
- The e2e flows already assert the words people read (`getByText(...)`), and the words do not change: a message that
  moves from a red line into a toast is still found by `getByText`. Three flows read `getByRole('alert')`
  (48-themes-v4, 72-designs, 75-staff-passkeys): each is re-pointed at the toast or field in the task that moves it.
- New helper `expectToast(page, text, kind)` in `e2e/lib.mjs`: the toast is visible, its kind, its role.
- `fixtures/ui/primitives` (the console's primitive board) gains every toast kind, a field-error form, an
  `<ActionForm>` and a Dialog with an error: one step each in `e2e/flows/30-primitives.mjs`.

## F0 · Primitives and the gate (console fixtures only; nothing a merchant sees changes yet)
1. **Toast kinds** (`src/components/ui/toast.tsx`): `toast({ text, undo })` keeps working (kind `ok`);
   `toast.error(text, { sub?, action? })` → kind `error`: no timer (stays until ×, Esc or its action), `role="alert"` on
   the toast (not announce()), × button, Esc closes; marks (check / !) with the `mark-pop` keyframe on `--ease-snap`.
   `toast.ok(text, { undo? })` alias. A newer toast replaces any (today's rule). Unit test: timers and kinds
   (`src/components/ui/__tests__/toast.test.tsx` with fake timers, if the test setup renders client components; else
   the fixtures e2e).
2. **One Toaster per surface**: mount `<Toaster>` in the console, Admin, partner, look editor, shop and the public
   layouts (login, start, handover, partners, ek, choose). Remove the island Toasters (queue, order-actions,
   ship-panel, domains, fixtures) — the layout's is above them. The shop's Toaster takes `tone="store"` (shop tokens).
3. **Field errors** (`src/components/ui/field-error.tsx`): `<FieldError id message />` (mark + line, `err-in`
   motion) and `useFieldErrors()` → `{ errors, set(map), clear(name), props(name) }`. `set` marks fields, focuses the
   first (DOM order), shows ONE error toast "N fields need fixing · Show" (noun configurable: "details" in the shop);
   `clear` on input counts it down; zero → the toast leaves. `props(name)` gives `aria-invalid`,
   `aria-describedby`, the danger edge class.
4. **Dialog error slot** (`ui/dialog.tsx`): `error?: string` renders the alert block above the actions (`err-in`).
   `LeaveDialog` (`ui/unsaved.tsx`) becomes a `Dialog`. The customizer's own toast (`customize/editor.tsx`) becomes
   `ui/toast`.
5. **Forms that post to the server say their result in a toast** (`src/components/ui/action-form.tsx`, client):
   `<ActionForm action={serverAction}>` posts the form, shows `toast.ok`/`toast.error` from the action's returned
   `{ ok?, error?, fields?, go? }`, marks `fields` with `FieldError` + the summary, checks the browser's constraint
   validity first (`required`, `pattern`, `min` stay the rules; `data-error` gives the words), refreshes the page,
   and follows `go` after the toast (the layout's Toaster outlives the move). No message travels in a URL or a
   cookie (security review 2026-11-12, MED-1/3, LOW-1/2/3: a flash cookie was designed and dropped for this).
6. **Gate** `scripts/check-feedback.mjs` (in `npm test`): in `src/app/**` and `src/components/**` outside the
   primitives, refuses (a) `<Notice`, (b) a read of `searchParams.error`/`sp.error`/`?error=` writes,
   (c) `role="alert"` on a `<p>`/`<span>`, (d) a `<p>` with `text-danger-text`. A ratchet file
   (`scripts/feedback-allow.json`: file → count, plus the rule-5 pinned sites by file:reason) may only go down;
   F3 ends with only rule-5 entries. Run against its own doc comment (CLAUDE.md: a gate must not match itself).
7. **Docs**: `frata-design-language` § Feedback names the primitives (done, 5.21.0); `frata-architecture` notes
   `flash()` for server-action redirects.

## F2 · Admin (27 sites)
1. Every `actions.ts` that redirects with `?error=`/`?ok=` returns `{ error }` / `{ ok, go? }` instead; every Admin
   form is an `<ActionForm>`; pages drop `<Notice>` and stop reading `searchParams.error/ok`.
2. The browser's `required`/`pattern`/`min` bubbles become `FieldError`s through `<ActionForm>`.
3. Staff gate and passkeys (`text-destructive` blocks) → `toast.error` / `Dialog` error slot.
4. e2e: 40-partners, 75-staff-passkeys and every Admin flow re-pointed; a test that `?error=Call+us` shows nothing.

## F3 · Shop, EkCode, sign-in, partner (32 sites)
1. Shop: `<Toaster tone="store">` in the shop layout (shop tokens, above the pay bar); bag load failure, order-view
   payment/invoice failures, drops consent → toast; checkout fields → `useFieldErrors` (noun "detail"); the
   rule-pinned blocks stay (failed payment's line above Pay, price changed, COD why, Pick a size, a code that doesn't
   apply).
2. EkCode: wrong phone/code stay at the field; network → toast; the locked line gets `role="alert"`.
3. Sign-in, start, partners/apply, partner new store: fields → `useFieldErrors`; failures → toast; handover's
   `?error=` → `<ActionForm>`. The shop never reads a result from a URL or cookie (MED-3); its Toaster dismisses on a
   path change and no shop toast carries shopper data.
4. Speed: shop first-load JS within its budget (`frata-architecture` § Speed) with the Toaster; checkout e2e.
