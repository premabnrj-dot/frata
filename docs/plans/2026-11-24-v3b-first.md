## Goal

North star (5): a partner builds a brand's website with Studio on a real store. Today Studio works only on a test store
with no owner, and charges nothing. Measure: the first partner turn on an owned store, paid in credits.

## K1 · Apply on a store with an owner or an open store

What changes (`src/lib/studio/apply.ts`, `src/lib/content/save.ts`, `src/lib/queries/studio.ts`, `src/domains/studio/proposals.ts`):
- The V3a refusal ("Change this in the store's own console") is gone. Apply runs `saveBrand` as before; `saveBrand`
  decides, by `brandSaver`, exactly as for the partner's own Brand save. No second review exists.
- **Not yet open** (with or without an owner): live at once, card "Applied". Same as a partner's own save (call 3).
- **Open**: `saveBrand` makes the store's one waiting change (`brand_proposals`, the Notices line, the review card on
  Console › Brand) and now returns its id. Apply records that id on the card (`studio_proposals.brand_proposal_id`, 0176)
  and never sets `applied_at`. The card reads **Sent to the owner**, then the change's own decision, read from
  `brand_proposals` at each chat read (`cardState`): **Approved**, **Declined by the owner**, **Replaced by a newer change**.
  The chat's poll carries every sent card of the session, so the outcome arrives without a reload while the chat polls.
- **A change already waiting**: the newer one takes its place (`saveBrand`, one open change a store). The older card,
  from Studio or from Brand, reads Replaced. A sent card can't be applied or set aside again.
- **The owner declines**: Declined by the owner; nothing changed on the store.
- **A stale version**: refused in saveBrand's words, nothing sent, Reload Brand (state 9), as before.
- **The agent can never approve**: approval is `decideBrand`, which requires `shop.manage` in person (the owner or a
  Manager, never a support visit). Studio runs as the `partner` role; the agent's tools (`src/lib/studio/tools/`) only
  propose; Apply is a person's action behind `requireStudio()` (the partner's passkey check, or passkeys off).
- 0176: one column, a composite foreign key (tenant, change) so a card can name only its own store's change, and its
  column grant. 508 bytes of SQL in 3 statements.

Tests: `src/lib/studio/__tests__/apply.int.test.ts` (no owner and unopened; owner present; open store; a change already
waiting; declined; approved; stale; another store's change refused by the key), `save.int.test.ts` (the id returned),
`src/domains/studio/__tests__/card-state.test.ts`.

## K3 · Turns charged in credits

What changes (`src/lib/studio/sessions.ts`, `src/lib/studio/credits.ts`, 0177):
- **Send** reserves first, through `reserveCredits` as the person (their partner, step-up and the store's live link):
  estimate = `creditsFor(turn ceiling, the day's rate)` with the 1.10 loading (frata-unit-economics § The dollar rate):
  $0.50 at ₹94.1997 is ₹51.81 loaded, **9 credits**. The database's own order then refuses: no fresh rate, Studio's day,
  the person's 300, the client's budget, the balance. Then the turn opens (the USD caps, unchanged, are the outer guard)
  and, in that transaction, `app_studio_turn_use` ties the use to the bound person's own open turn (and marks the turn no
  longer a staff test). A refusal or failure before the turn opens gives every credit back at once.
- **The turn's end**: every V3a end already passes the one internal `app_studio_settle` once its cost is known. It now
  settles the use with the raw measured cost (`app_pc_settle`: at the use's stored rate, credits never above the reserve,
  the rest released; the raw figure kept so an overshoot past the ceiling is seen), or returns every credit for a failure
  on our side or an expiry. `app_studio_end_session` records the end before it settles,
  so the settle reads why.

| V3a end state | Credits | Reason |
|---|---|---|
| ended (end_turn) | settle, measured | |
| paused (budget_reached) | settle, measured; Continue is a new Send with its own reserve | |
| failed: runtime (advance), start, send, budget raise, workspace | return | frrata |
| Stop (session `stopped`), store switch, person removed (`actor`) | settle, measured (the person's choice; its proposals stay usable) | |
| expired (idle, age, a start that died) | return | timeout |
| a dollar-cap or sessions refusal after the reserve | return | frrata |
| a turn still open, or a Send at the same moment (`busy`) | return | cancelled |
| the process dies between the reserve and the turn | the credits run's stale sweep | timeout |
| a cost never read (Anthropic down) | the reserve stays held until the clean-up settles it, else the stale sweep | timeout |

- **Refusal words** (§ 3, the Credits and billing page's own): rate "Studio can't start a turn right now. Try again in a
  few minutes."; Studio's day "Studio is busy today. Try again tomorrow."; the person's day "You've used 300 credits
  today. Try again tomorrow."; budget "This client's budget is used up." with Raise by 50, or "Ask Kabir to raise it." for
  a Lead; balance "Not enough credits. Buy credits to continue." with Buy 100 credits, or "Ask Kabir to buy credits." for a
  Lead. The server returns each as its own `SendWhy` (`rate`, `studio_day`, `credits_day`, `client_budget`, `balance`);
  the composer's words wait for the owner's yes on § 3.
- **Staff test turns: charged** from the partner's credits like anyone's, so the test is real (call 1; the owner's test
  partner has 20 free credits: 3 typical turns of 4, then 8 stranded, since a reserve of 9 refuses at 8). For the owner to
  confirm.
- **Open from the unit-economics review, for the owner:** (a) stranded credits: up to 8 of a partner's credits can't pay
  for a turn; fix by reserving `min(9, balance)` from 4 and lowering that turn's USD ceiling to match (`microUsdFor`);
  (b) a test lot of about 300 credits for the staff test partner, which pays only while money is not real, so the 30-day
  staff test runs; (c) the credits run's stale sweep returns a never-read turn whole (up to ₹51.81 of list cost each):
  read the archived session's cost and settle before returning. Returns at a 5/3/1 stop/fail/timeout mix were 7.2% of
  list cost with Stop returned; with Stop charged, inside the loading's 5% allowance.
- **The credits panel** (`credits/studio-panel.tsx`) is drawn in the approved four-screens § 1 (the pill opens it), so
  mounting it is as drawn. Not mounted yet: it brings Buy credits' and Raise budget's dialogs into Studio's page, which
  is pinned at 133.4 kB with 0.5 kB of room; a production build must measure it first.
- 0177: one column with its unique key, one new definer (`app_studio_turn_use`, executed by `frata_app` only), two
  replaced (`app_studio_settle`, `app_studio_end_session`, `app_pc_stale_uses`). 8,296 bytes of SQL.

Tests: `src/lib/studio/__tests__/sessions.int.test.ts` § V3b K3 (the estimate; a Send holds 9 tied to its turn; the end

## Recorded, not fixed
| Finding | Why it stands | What closes it |
|---|---|---|
| security L2: a turn the runtime fails (`refusal`, `retries_exhausted`) gives every credit back, even after tools ran and their cards stay usable | a refusal after paid work is unconfirmed; returning keeps "a failure of ours costs you nothing" | charge what was measured when a tool call ran, if the staff test shows it |
