## Review findings

### tenancy-auditor (2026-11-07): fix in the plan before step 1
| Sev | Finding | Fix (binding on the build) |
|---|---|---|
| HIGH | Embedded Signup hands `waba_id`/`phone_number_id` to the **browser**: a forged id could claim another shop's number | The server reads both ids from the exchanged token (`debug_token` granular scopes → `/{waba}/phone_numbers`) and ignores the client's. Partial unique index on open rows for `phone_number_id` and `waba_id`. e2e with a forged id |
| HIGH | Webhook routing under-specified | `app_tenant_for_wa(pnid)` and `app_tenant_for_waba(id)`: open rows only, format `^[0-9]{5,20}$`, `search_path=''`, return tenant_id only, EXECUTE revoked from public/anon/authenticated. Route and store **per change** (one POST batches several entries). Unknown id: store nothing, answer 200. Proofs: duplicate open ids fail; closed A + open B routes to B; closed alone → nothing; bad format → nothing |
| HIGH | Blob store is public and tenant paths are already visible | Private store, or a 128-bit random name under `tenants/<id>/wa/`. The URL never reaches a browser. Served by `/api/console/media/[messageId]` (`requireMember`, path looked up by message id inside `withTenant`, partner check, `private, no-store`). `PATH_SHAPE` keeps refusing `wa/` |
| HIGH | Inbox visibility is app-only (RLS can't tell roles apart) | One `canSeeChats(membership, settings)` read by every inbox query, action, the polling endpoint, the media route and the `customer.side` slot. e2e: a partner is refused at each. Support sends carry actor `support` |
| MED | Cross-tenant references | Composite FKs `(tenant_id, x_id)` on contacts, conversations, messages (and `order_id`), notes, reads, presence, consents, `assigned_to` → members. Proof: A can't point at B's conversation |
| MED | Outbox sender | Payload holds no token and no pnid. The sender opens `withTenant` and reads the **open** connection at send time. `seal(token, tenantId, 'wa_token')`. Drop `pin_enc` unless needed |
| MED | Button replies | Find the order by `context.id` (the replied-to wamid) → `messages.order_id` inside the routed tenant. Never from payload text |
| MED | Webhook key | `whatsapp:<tenant>:<pnid>:<wamid>:<status>`, so delivered and read for one wamid don't collapse into one row |
| MED | frata_admin | No grant on any communication table. Proof: admin read raises |
| LOW | Modules plan text | Platform tables use a select policy, like plans' `catalogue_read` (not a definer). Proofs: frata_app can't write `tenant_addons`, `addon_prices` or `module_pauses`, or B's `tenant_modules`; a second open switch row fails; admin inserts but can't update `tenant_addons`. A pause revalidates every shop's tag |
| LOW | Polling endpoint | Calls `requireMember` itself; tenant from the membership; never cached; logs no bodies or phones |
| LOW | Checkout consent | The contact's tenant comes from `tenantForHost()`, never a form field |
