# Look v4: site settings, icons, menus, page-aware editing

Status: P1 + P2 built (owner approved 2026-11-09: "Build P1 + P2"; theme switch "Theme's own"; Lucide + Phosphor) · Date: 2026-11-09 · Mockup: https://claude.ai/artifact/MmC6BnAps1XXSWyfy7PfSL (`docs/mockups/2026-11-09-look-v4.html`)
North star: (5) a premium-looking storefront and (4) mobile checkout conversion; a brand that looks like itself on
every page, set once, without a developer. Sources carry their page's date; "undated" = read live 2026-11-09.

## 0. Summary
1. **Three layers, one cascade:** **Site settings** (the brand: palette, type, buttons and fields, icons, identity)
   → **Theme settings** (the theme's own choices: layouts, header and footer designs, motion) → **Page settings**
   (each page's options, offered per theme) → a section's own override, always with "Use site setting" to undo it.
   This is Elementor 4.0's variables → defaults → local class, and Shopify Horizon 4.0's palette + font roles.
2. **Site settings behind a gear** at the top of the customizer, separate from Theme settings. They survive a theme
   switch (they are the merchant's brand); a theme only supplies their starting values.
3. **Icons as data, rendered as inline SVG on the server**, only the icons a page uses: no icon font, no client JS.
   Three styles: Line (Lucide, ISC), Duotone and Solid (Phosphor, MIT). One stroke weight setting.
4. **Menus**: Main, Footer and Phone tabs; a drag-to-nest tree, 3 levels at most, an icon per item (beside its text,
   never instead of it), links only to the shop's own pages.
5. **Page-aware editing**: the top bar says which page is being edited; opening a page's options opens that page in
   the preview (a product, a collection, the bag, the checkout), and the options shown are that page's, from the
   theme. A collapsible panel (a rail of icons when closed).
6. **Phases P1–P4** (§ 8). P1: site settings, page-aware, collapsible panel. P2: icons, menus, bag and checkout pages.

## 1. Where we are (code, 2026-11-09)
- Shop menu = the first five collections, alphabetical (`shopSettingsFor` › `nav`); no menus to manage.
- The shop has no icon system: the header's menu is a "≡" text character (design-language: no glyph as an icon);
  Bag is a word. The console has its own two-stroke icons (`src/components/icons/icon.tsx`).
- Colour comes from a theme's styles (schemes Paper / Tint / Ink) plus one brand colour; type is a pairing
  (display + Inter) and a size step. No per-level type, no palette of the merchant's own.
- The customizer has a page picker (Home / A product / A collection); Bag and Checkout aren't editable or previewable.

## 3. Site settings (the gear)
| Group | What | Rule |
|---|---|---|
| Colours | Six system roles (Primary, Accent, Background, Surface, Text, Muted) + up to 6 own colours, named; palette presets from the theme | Roles can't be deleted; every pair a page uses is contrast-checked as it is picked ("Reads well") |
| Typography | Four font roles (Display, Heading, Body, Accent) from the curated families; text styles Display, H1–H4, Body, Small, Button, Price, each = a role + size (computer / phone) + weight + case + spacing | Sizes are a scale with a computer and a phone value; Price is tabular |
| Buttons and fields | Primary, Secondary, Text link; fields | Shape, corners, hover; from the type and colour styles |
| Icons | Line / Duotone / Solid; stroke Thin / Regular / Bold | One library for the whole shop |
| Brand | Logo (wide, square, on dark), tab icon, share image | Moved from Settings › Brand; one source |
Storage: a `site` block in the look's layer (draft → publish → undo like everything else), carried whole when the
merchant tries another theme. A theme supplies starting values only.

## 4. Theme settings (the theme's own)
What a theme offers (choicesFor, as today): header and footer designs, layouts, card style, motion, rhythm. Shown
under the theme's name, so the merchant sees what changes with a theme and what doesn't.

## 5. Page settings (per theme, page-aware)
Pages: Home, Product, Collection, Shop all, Search, Bag, Checkout, Not found. Each page's options come from the
theme's manifest (`pages: { product: {...} }`); the customizer opens that page in the preview when its group opens
("Editing: Product page"), with "Preview with" a chosen product or collection. Bag and Checkout options are the same
for every theme (they hold money: one well-tested layout each, styled by Site settings).

## 6. Icons
- `src/domains/icons/` (pure data): a curated set of ~100 commerce icons (bag, cart, search, user, heart, truck,
  return, cash, UPI, WhatsApp-style chat, tag, sparkle, size, ruler, gift, lock, star…) × three styles, as SVG path
  data with a stroke or fill-with-tone flag. Licences listed in `NOTICE`.
- `<ShopIcon name>` renders inline `<svg>` on the server with `currentColor` and `--icon-stroke`; duotone's second
  layer is the same colour at low opacity (one token). Only the icons a page uses are in its HTML.
- Gate: `check:storefront-build` fails a shop chunk that holds icon data (icons are server-only); a page's icon bytes
  stay under 6 kB. *(Built: the chunk gate. Not built: the 6 kB per-page measure.)*

## 7. Menus
- Three menus: Main, Footer, Phone tabs (4–5 items, each with an icon). Items: label (≤ 40), link (a shop path picker:
  collection, product, page, policy), icon (optional), children (3 levels at most). A soft warning past 7 top items
  or 10 children (Baymard).
- The phone drawer: categories first, "View all" at each level, the current page marked, small collection pictures.
- Default menus are made from the collections, as today, until the merchant edits one.
- Stored in the look's layer (`menus`), validated by Zod at every save; links are the shop's own paths (`shopPath`). *(Not built: a check that a linked collection or product still exists; a dead link opens the shop's Not found page.)*

## 9. Owner calls
1. Site settings **survive a theme switch** (the brand is the merchant's), a theme supplies starting values only. *Recommended.* **Owner: "Theme's own"** (2026-11-09): a new theme brings its own palette, type and icons; menus are content and come across; another version of the same theme keeps both.
2. Icon libraries: **Lucide (line) + Phosphor (duotone, solid)**, a curated ~100 icons, inline SVG. *Recommended.*
3. Menus: **3 levels**, icons beside text, never alone. *Recommended.*
4. Bag and Checkout options **the same for every theme** (money pages). *Recommended.*
5. Phase order P1 → P4. *Recommended.*

## How Frrata outranks the rest (the bets)
- **Phone-first editing** (Canvas is desktop only): every control works with a thumb.
- **Fewer decisions:** brand kits and theme defaults, then fine-tuning; nothing a merchant must set to look good.
- **Truthful by construction:** promises from shop facts, contrast checked as you pick, legal lines that can't be removed.
- **Fast by construction:** icons, motion and type are data; the shop's script budget doesn't move.
- **Judged on profit:** tests and suggestions measured on delivered orders, the number Frrata already computes.
